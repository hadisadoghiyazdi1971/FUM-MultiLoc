# Contributing

FUM-MultiLoc is currently in the specification phase.

## Before opening a contribution

1. Do not attach raw participant images, unredacted maps, Wi-Fi MAC addresses, cellular infrastructure identifiers, or other potentially sensitive research material to public issues or pull requests.
2. Keep changes to schemas backward-compatible when possible.
3. Document any change that affects evaluation, coordinates, synchronization, splits, or metric definitions in `CHANGELOG.md`.
4. Generated benchmark scores must state the exact benchmark version.

## Pull requests

A pull request should explain:

- what changed;
- why the change is needed;
- which schema/protocol/task is affected;
- whether results produced by older benchmark versions remain comparable.
